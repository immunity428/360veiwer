# vrmap

花火大会のチケットを買う前に、座席から見える景色を360度グルっと確認できるWebサービスです。

---

## 背景

### 課題

諏訪湖祭湖上花火大会のチケット販売において、既存の座席紹介サイトでは以下の問題がありました。

- **木・建物などの障害物**により、座席によっては花火が見切れてしまう
- 購入後に「思っていた眺めと違う」というクレームが発生していた
- **静止画による場所の写真のみ**の掲載で、実際の見え方・雰囲気が伝わりにくい
- **実際の現地との乖離**があり、サイトの情報と現地の状況が一致しないケースがある

これらはすべて、座席の「見え方」が購入前にわからないことに起因しています。

### 解決策

**Insta360** で各座席から360°撮影し、会場マップ上のピンに紐づけて公開します。来場者はチケット購入前に、実際の座席の視点から花火の見え方を確認できます。

---

## 利用フロー

```
会場マップ（エリアのピン）
  ↓ タップ
エリア拡大マップ（座席のピン）
  ↓ タップ
360°パノラマビュー ＋ チケット購入ボタン
```

- 拡大マップと360°画像は、開いたときに初めて読み込まれます（初期表示を軽くするため）
- 360°ビューア（Pannellum）本体も、最初に360°ビューを開いたときに読み込みます
- 閉じる操作は × ボタンのみ（誤タップで戻らないように）

## 技術選定

### 選定の観点

| 観点 | 内容 |
|---|---|
| **規約** | 商用・業務利用における利用規約のグレーゾーンをなくす |
| **管理コスト** | 運用・保守にかかる工数を最小化する |
| **コーディング難易度** | 後任担当者が引き継ぎやすい構成にする |
| **内部仕様** | 帯域・同時アクセス数（想定10万人）への対応 |
| **継続性** | サービス停止・値上げリスクの低い選択をする |

### 構成の変遷：バックエンドありの構成から静的サイトへ

当初は「Vercel Pro ＋ Cloudflare Workers / D1 / R2 ＋ 管理画面」の構成で開発しました。しかし運用要件を整理すると、

- 撮影スポットは5エリア・25席程度
- 画像やチケットURLの更新は年1〜3回

と、データベースや管理画面を持つほどの更新頻度・データ量がないことがわかりました。そこで **すべての画像とデータをリポジトリに含めた静的サイト** に切り替えました。

| | 旧構成 | 現構成 |
|---|---|---|
| ホスティング | Vercel Pro（$20/月） | Cloudflare Pages（無料・商用利用可） |
| データ | D1 ＋ Workers API | `spots.json` 1ファイル |
| 画像 | R2 | リポジトリの `public/images/` |
| 管理画面・認証 | あり（パスワード管理が必要） | なし（攻撃対象がない） |
| 運用費 | 約$25/月 | ドメイン代のみ |
| デプロイ | フロントとWorkerを別々に | GitHubにpushするだけ |

管理画面がなくなる分、データの入力ミスを防ぐ仕組みとして **JSON Schema（VS Codeで入力補完・エラー表示）** と **ビルド前の自動チェック** を用意しています。

### Cloudflare Pages を選んだ理由

| サービス | 規約 | 管理コスト | 継続性 | 結論 |
|---|---|---|---|---|
| **Cloudflare Pages** | ✅ 無料プランで商用利用可 | 低 | ◎ | **採用** |
| Vercel | ⚠️ 無料プランは商用利用不可（Pro $20/月が必要） | 低 | ◎ | コスト面で不採用 |
| GitHub Pages | ⚠️ 商用利用がグレー | 低 | ○ | 規約上不採用 |
| AWS S3 + CloudFront | ✅ | 高 | ◎ | 後任の継続難易度が高いため不採用 |

### 制約

- Cloudflare Pages の1ファイル上限は **25MiB**、ファイル数上限は無料プランで20,000です。360°画像は圧縮して1枚数MBに収めます（下記）。
- 画像を差し替えても古い画像はGitの履歴に残ります。年数回・数MB単位の更新なら問題ない規模です。

    └── check-spots.mjs           # spots.json の自動チェック

## spots.json の書き方

```jsonc
{
  "map": { "image": "images/map.png", "alt": "会場概略図", "credit": "会場概略図：…" },
  "areas": [
    {
      "id": "center",                       // 英小文字・数字・ハイフン。重複不可
      "label": "中央エリア",                 // ピンに表示する名前
      "x": 53.1, "y": 78.7,                 // 会場マップ上のピン中心（%）
      "description": "…",
      "detailMap": "images/areas/center.jpg",// 拡大マップ（未作成なら null）
      "detailMapCredit": "航空写真：国土地理院（地理院地図）",
      "seats": [
        {
          "id": "center-premium",
          "label": "プレミアムマス",
          "x": 50.5, "y": 40.0,             // 拡大マップ上のピン中心（%）
          "panorama": "images/panoramas/center-premium.jpg", // 未撮影なら null
          "ticketUrl": "https://…",          // 未定なら null（ボタン非表示）
          "view": { "pitch": 0, "yaw": 0, "hfov": 100 }      // 360°の初期視点
        }
      ]
    }
  ]
}
```

- 画像のパスは `public/` からの相対パスで書きます（先頭に `/` は付けない）
- `x` / `y` は画像の左上を (0, 0)、右下を (100, 100) としたピンの**中心**の位置です
- VS Code で開くと、各項目にカーソルを合わせたときに説明が表示され、間違った値には赤線が出ます

### 360°画像の用意

- Insta360 から **正距円筒図法（2:1）の JPEG** で書き出す
- **4096×2048px** に縮小して保存（スマホでも確実に表示でき、1枚数MBに収まる）
- ファイル名は座席の `id` に合わせると管理しやすい（例: `center-premium.jpg`）

## 更新手順（年1〜3回）

1. 画像を `public/images/panoramas/`（または `areas/`）に入れる
2. `src/data/spots.json` の該当座席の `panorama` / `ticketUrl` などを書き換える
3. チェックを実行する

   ```bash
   npm run check
   ```

   ファイル名の間違い、座標の範囲外、IDの重複、URLの形式などがあればエラーで教えてくれます。

4. ローカルで見た目を確認する

   ```bash
   npm run dev   # → http://localhost:5173
   ```

5. コミットして push すると、Cloudflare Pages が自動でビルド・公開します

   ```bash
   git add .
   git commit -m "update: 2027年の座席画像を差し替え"
   git push
   ```

> `npm run build` の前にも同じチェックが自動で走るため、spots.json にエラーがある状態では公開されません。

## セットアップ

```bash
npm install
npm run dev
```

Node.js 18以上が必要です（`.nvmrc` で 22 を指定しています）。

### Cloudflare Pages へのデプロイ（初回のみ）

1. Cloudflare ダッシュボード → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. このリポジトリを選択し、以下を設定
   - Framework preset: `Vite`（または None）
   - Build command: `npm run build`
   - Build output directory: `dist`
3. 独自ドメインを使う場合は、プロジェクトの **Custom domains** から追加

環境変数・シークレットは不要です。
